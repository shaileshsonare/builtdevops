Docker & Kubernetes Tutorial

Welcome! In this tutorial, we will learn how to take a simple website and turn it into a high-performance, auto-scaling application using Docker and Kubernetes.

Target: By the end of this guide, you will have 10 copies of your website running simultaneously, all sharing the same source code from your local computer!

Cloud Concepts

1. What is an Image?

An **Image** is like a frozen snapshot of a computer. It contains the OS, the language (PHP), and your settings. It doesn't "run", it's just a file.

2. What is a Container?

A **Container** is what you get when you start an Image. It is a living, breathing instance of your application. You can have many containers running from one single Image.

3. What is a Volume?

A **Volume** is a bridge. It connects a folder on your real computer to a folder inside the container. This lets you edit code on your desktop and see results in the container instantly.

Phase 1

Step 1: Create the PHP Script

First, we create our website logic. We will add a "Session Counter" so we can see if our sticky sessions are working.

Create a file named index.php:

File Name: index.php
<?php
session_start();
if (!isset($_SESSION['counter'])) {
    $_SESSION['counter'] = 1;
} else {
    $_SESSION['counter']++;
}
echo "<h1>PHP Session Test</h1>";
echo "<p>Counter: " . $_SESSION['counter'] . "</p>";
echo "<p>Pod Name: " . gethostname() . "</p>";
?>

Phase 2

Step 2: Create the Dockerfile

The Dockerfile is the "Blueprint" for our Image. We will use the PHP-FPM image because we want to use Nginx later.

Create a file named Dockerfile:

File Name: Dockerfile (No extension)
FROM php:8.2-fpm-alpine
RUN mv "$PHP_INI_DIR/php.ini-production" "$PHP_INI_DIR/php.ini"
WORKDIR /var/www/html

Phase 3

Step 3: Create Nginx Config

Nginx is our web server. It needs to know that any request for .php files should be sent to the PHP service.

Create a file named nginx.conf:

File Name: nginx.conf
server {
    listen 80;
    root /var/www/html;
    index index.php;

    location ~ \.php$ {
        fastcgi_pass php-app:9000;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}

Phase 4

Step 4: Docker Compose & Scaling

Now we bring them together. Create a file named docker-compose.yaml:

File Name: docker-compose.yaml
services:
  php-app:
    build: .
    volumes:
      - .:/var/www/html
  nginx:
    image: nginx:alpine
    ports:
      - "8081-8090:80"
    volumes:
      - .:/var/www/html
      - ./nginx.conf:/etc/nginx/conf.d/default.conf

How to Scale (Copies)

To run 3 copies on your computer right now:

Run in Terminal:
docker compose up -d --scale php-app=3

Phase 5

Step 5: Define Kubernetes Files

Kubernetes needs 3 specialized files to run your app professionally. We will create them one by one.

A) The Deployment (The Brain)

This file tells Kubernetes to run 2 pods, each with an Nginx sidecar and PHP. It also maps your local folder.

File Name: k8s-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: php-hello-world
spec:
  replicas: 2
  selector:
    matchLabels:
      app: php-app
  template:
    metadata:
      labels:
        app: php-app
    spec:
      hostAliases:
      - ip: "127.0.0.1"
        hostnames: ["php-app"]
      containers:
      - name: php-fpm
        image: php-hello-world:latest
        imagePullPolicy: Never
        volumeMounts:
        - name: php-volume
          mountPath: /var/www/html
      - name: nginx
        image: nginx:alpine
        volumeMounts:
        - name: php-volume
          mountPath: /var/www/html
        - name: nginx-config
          mountPath: /etc/nginx/conf.d/default.conf
          subPath: nginx.conf
      volumes:
      - name: php-volume
        hostPath:
          path: /home/shaileshsonare/Desktop/phpdocker
      - name: nginx-config
        hostPath:
          path: /home/shaileshsonare/Desktop/phpdocker/nginx.conf

B) The Service (The Doorway)

This file creates a stable URL (port 30080) for you to access the website.

File Name: k8s-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: php-service
spec:
  type: NodePort
  sessionAffinity: ClientIP
  selector:
    app: php-app
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
      nodePort: 30080

C) The HPA (The Auto-Scaler)

This tells Kubernetes to automatically grow from 2 to 10 copies if the CPU gets busy.

File Name: k8s-hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: php-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: php-hello-world
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50

D) Apply all files

Once you have created all three files, run this in your terminal:

kubectl apply -f k8s-deployment.yaml
kubectl apply -f k8s-service.yaml
kubectl apply -f k8s-hpa.yaml

How to Test your Application

After you have applied all your files, follow these steps to prove that your "Cloud App" is working!

1. Test Docker Compose

Open your browser and visit:

http://localhost:8081

2. Test Kubernetes

Open your browser and visit:

http://localhost:30080

3. Test the "Shared Volume" (Live Sync)

This is the coolest part! Try this:

  • Keep your browser open.
  • On your desktop, open index.php in Notepad or VS Code.
  • Change the word "PHP Session Test" to "HELLO STUDENTS".
  • Press Save.
  • Refresh your browser!

The text changes instantly without you needing to restart any container.

4. Verify Scaling

To see how many copies are running, look at the "Pod Name" line. If you open the website from a different browser or private tab, you might see a different Pod name! You can also run:

kubectl get pods

Automatic Scaling (HPA)

The HPA (Horizontal Pod Autoscaler) is like a manager. It watches how tired the servers (Pods) are. If they use more than 50% CPU, it creates more copies automatically!

How to test it:

1. Start watching the pods:

kubectl get pods -w

2. Put load on the server:

while true; do wget -q -O- http://localhost:30080; done

You will see K8s create up to 10 pods to handle this load!

Start and Stop: Controlling your Gear

Containers are like lightbulbs. You should turn them on when you need them and off when you are done to save your computer's memory.

1. Docker Compose

To Start: Runs the containers in the background.

docker compose up -d

To Stop: Stops and removes the containers completely.

docker compose down

2. Kubernetes (K8s)

To Start: Applies all your YAML files at once.

kubectl apply -f .

To Stop: Deletes everything defined in your YAML files.

kubectl delete -f .
Pro Tip: In the Kubernetes command, the dot (.) means "The current folder". Kubernetes will automatically find all .yaml files and apply or delete them for you!

Troubleshooting & FAQs

Error: Port already in use
Close the app that is using port 80 or 8081, or change your config to use a different port like 8099.
Q: Why does the Pod Name not change?
Because we enabled Session Affinity. This "sticks" a user to one pod so their Login Session stays valid.
Q: Is my code saved in the Image?
No, we used a Volume. This means the container lives empty and "borrows" the files from your Desktop folder while it runs.
