Node.js Docker & K8s Tutorial

In this guide, we will build a High Performance Node.js API. We will learn how to make it run anywhere and scale perfectly across a cloud cluster.

Target: Create an API that tracks how many times you visit, proving that your "Sticky Sessions" are working across 10 replicas!

Phase 1

Step 1: Create the Node App

Create a file named app.js:

File Name: app.js
const express = require('express');
const session = require('express-session');
const app = express();
const os = require('os');

app.use(session({
    secret: 'cloud-secret',
    resave: false,
    saveUninitialized: true
}));

app.get('/hi', (req, res) => {
    req.session.counter = (req.session.counter || 0) + 1;
    res.send(`
        <h1>Node.js Session Test</h1>
        <p><b>Counter:</b> ${req.session.counter}</p>
        <p><b>Pod Name:</b> ${os.hostname()}</p>
        <p><b>Time:</b> ${new Date().toLocaleString()}</p>
    `);
});

app.listen(3000, () => {
    console.log('API listening on port 3000');
});

Phase 5

Step 5: Define Kubernetes Files

Kubernetes needs 3 specialized blueprints to run your app professionally in the cloud.

A) Deployment

File Name: deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: node-api
spec:
  replicas: 2 # Start with 2 copies of your app
  selector:
    matchLabels:
      app: node-api
  template:
    metadata:
      labels:
        app: node-api
    spec:
      containers:
      - name: node-api
        image: node-hello-api:latest # This is your custom Node image
        imagePullPolicy: Never # Use the image already on this computer
        ports:
        - containerPort: 3000 # The app inside the container uses port 3000

B) Service

File Name: service.yaml
apiVersion: v1
kind: Service
metadata:
  name: node-service
spec:
  type: NodePort # Makes the app accessible to the outside world
  sessionAffinity: ClientIP # Enable 'Sticky Sessions' so users stay on 1 pod
  selector:
    app: node-api # Connects this service to our deployment
  ports:
    - port: 3000
      targetPort: 3000
      nodePort: 30001 # Access the app in browser at localhost:30001

C) The HPA (The Auto-Scaler)

File Name: hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: node-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: node-api # Manage scaling for our node-api deployment
  minReplicas: 2 # Floor: Never go below 2
  maxReplicas: 10 # Ceiling: Never go above 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50 # Create more if CPU usage hits 50%

D) Apply all files

kubectl apply -f .

Understanding Scaling & Flags

1. Docker Compose Scaling

docker compose up -d --scale node-api=5
The Flag: --scale
Tell Docker: "I want exactly 5 copies of the node-api service running right now."

2. Kubernetes Auto-Scaling

kubectl autoscale deployment node-api --cpu-percent=50 --min=2 --max=10
Breakdown of Flags:
  • --cpu-percent=50 : The "Tiredness" limit. If a pod uses more than 50% CPU, Kubernetes creates a new copy!
  • --min=2 : The Floor. Never go below 2 copies (for safety).
  • --max=10 : The Ceiling. Don't go above 10 copies (to save money/memory).
